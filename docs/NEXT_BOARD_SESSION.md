# งานรอบหน้าที่มีบอร์ด (เตรียมไว้ 2026-11-28)

รวมทุกอย่างที่ต้องใช้บอร์ดจริง พร้อมของที่ต้องซื้อ ทำตามลำดับในหัวข้อ 5 ได้เลย สถานะโปรเจกต์ดูที่ `docs/ROADMAP.md`

## 1. ของที่ควรซื้อ

| ชิ้น | ค่าที่แนะนำ | ทำไม |
|---|---|---|
| ซีเนอร์ | **2.7 V, 3.0 V, 3.3 V** 0.5 W (เช่น 1N5223B / 1N5225B / 1N5226B หรือ BZX55C2V7 / C3V0 / C3V3) | บอร์ดขับที่ A ≈ 4.66 V จะเห็นหัวเข่าฝั่งย้อนได้ต้องมี Vz < A/1.3 ≈ 3.6 V (`synth.py` ใช้กฎเดียวกัน) ซีเนอร์ 5.1 V จะดูเหมือนไดโอดธรรมดา |
| ตัวเหนี่ยวนำ | **47 mH, 100 mH, 220 mH** (และ 1 H ถ้าหาได้) ที่ DCR ต่ำ (ดูข้อ 2) | วัดที่ 1 kHz ได้ทั้งหมด; 10 mH เล็กเกิน (\|Z\|/Rr 0.29 และต้อง DCR ≤ 7.9 Ω) |
| C ค่าใหญ่ไม่มีขั้ว | ฟิล์ม **1 µF และ 10 µF** (polyester / polypropylene) | ทดสอบ auto-range ที่ความถี่ต่ำ (10 µF → 90.9 Hz + Rr 220) โดยไม่ต้องห่วงเรื่องขั้ว |
| C เล็ก | 1 nF ที่สั่งไว้ทำ C5/C6 (ใช้ตัวที่เหลือเป็น DUT) | 1 kHz + Rr 100k (\|Z\|/Rr 1.59): ทดสอบตำแหน่ง Rr 100k กับ C |

**ยังไม่ซื้อ:** ตัวเก็บประจุอิเล็กโทรไลต์ AC ±4.66 V กลับขั้วมัน ต้องรอวงจรมี DC bias หรือแอมพลิจูดต่ำ

## 2. ระวัง: ตัวเหนี่ยวนำ Q ต่ำ โมเดลอาจเรียกว่าเสีย

`synth.py` นิยาม L ดีว่า Q = 8–100 ที่ความถี่ทดสอบ, DCR สูง Q = 0.4–2.1 และขดลวดลัด L × 0.2–0.4 กับ Q = 1–3 ช่วง Q 2.1–8
ไม่มีในข้อมูลเทรนเลย choke เล็กราคาถูกมักมี DCR สูง เช่น 100 mH ที่ DCR 150 Ω ได้ Q ที่ 1 kHz = 628/150 = 4.2 ซึ่งโมเดลอาจตอบ FAULTY
ทั้งที่ของดี (เหมือนกรณี DF ของ C เซรามิกที่ต้องขยายช่วงของดีเป็น 6 %)

| L | ความถี่ + Rr ที่ auto-range เลือก | X<sub>L</sub> | DCR สูงสุดที่ยังเป็น “ดี” (Q ≥ 8) |
|---|---|---|---|
| 22 mH | 1 kHz, Rr 220 | 138 Ω | 17 Ω |
| 47 mH | 1 kHz, Rr 220 | 295 Ω | 37 Ω |
| 100 mH | 1 kHz, Rr 1k | 628 Ω | 78 Ω |
| 220 mH | 1 kHz, Rr 1k | 1.38 kΩ | 173 Ω |
| 1 H | 1 kHz, Rr 10k | 6.28 kΩ | 785 Ω |

- ก่อนซื้อ ดู DCR ใน datasheet ให้ต่ำกว่าคอลัมน์ขวา
- ก่อนวัด วัด DCR ด้วยมิเตอร์ แล้วคำนวณ Q = X<sub>L</sub>/DCR แผน `collect.py l` ติด label `boundary` ไว้ก่อน ถ้า Q ≥ 8 ค่อยแก้เป็น `good`
  ใน `labels.csv` (ใส่ค่า DCR ไว้ในช่อง reference ด้วย)
- ถ้าตัวที่หาได้ Q ต่ำทั้งหมด ผลที่ได้จะบอกว่าต้องขยายช่วง “L ดี” ใน synth หรือไม่

## 3. เปลี่ยน C5/C6 เป็น 1 nF

1. ถอด USB แล้วเปลี่ยน C5 และ C6 เป็น 1 nF **พร้อมกันทั้งคู่** (ต้องค่าเดียวกัน ไม่งั้นสองช่องหน่วงไม่เท่ากัน)
2. เสียบ USB ใช้ `case1_frontend_mf` เหมือนเดิม
3. zero-cal ใหม่ (ไม่มี DUT): ช่อง board พิมพ์ `zero` → `tools/zero_capture.txt` แล้วคัดลอกเป็น
   `hardware/captures/<วันที่>_mf1k_zero_ref_noDUT_1nF.txt` พร้อมเพิ่มแถว `zero` ใน `labels.csv`
4. วัด noise ตอนไม่มี DUT (คำสั่งใน `docs/CASE1_WIRING.md` ขั้นที่ 6) เทียบกับ ~11.5 count ตอน 100 pF
5. R 988 Ω ไล่ความถี่ 1000 → 1 Hz (ส่ง `f <hz>` ทีละค่า หรือรัน `autorange.py` หลายรอบ) เทียบตาราง ADC step 3:
   ถ้า error ~1 % ที่ 91–333 Hz เปลี่ยน แปลว่าเกี่ยวกับขาเข้า ADC
6. ช็อตไล่ความถี่ซ้ำ (gain และเวลาระหว่างสองช่อง)
7. วัด R ชุด 1 % บางค่าซ้ำ เช่น `python3 hardware/collect.py r --only R100,R1k,R10k,R100k` และ C 0.1 µF ดูว่ายังอยู่ใน ±1.5 %
8. `python3 hardware/eval_real.py` ต้องยัง 52/52 (capture เก่าใช้ zero-cal ของมันเอง)
9. บันทึกผลใน `docs/CASE1_WIRING.md` เป็น ADC step 4

## 4. ทดสอบ offset drift แบบยาว

ใช้ LED ทิศปกติที่ Rr 1k (ตอน LED ไม่นำไฟ node B ควรเป็น 0 V พอดี) แล้ว capture ทุก 1 นาที นาน 30 นาที:

```bash
for i in $(seq 30); do
  python3 hardware/reader.py --port <port> --frontend --rr 1022 --zero tools/zero_capture.txt --cycles 16
  sleep 60
done 2>&1 | tee drift_30min.log
```

`reader.py` พิมพ์ว่าช่องอ้างอิงเลื่อนไปกี่ count ทุกรอบ จากนั้นถอด USB เสียบใหม่ แล้วทำซ้ำอีก 5 รอบ เกณฑ์ผ่าน: baseline ของ node B
หลังแก้ด้วยช่องอ้างอิงอยู่ใน ±25 mV ตลอด (ทดสอบ 2 นาทีเมื่อ 2026-11-27 ได้ ≤ 25 mV)

## 5. ลำดับแนะนำ

1. ข้อ 3 (C5/C6 → zero-cal → noise → R ไล่ความถี่) สำคัญที่สุด เพราะตอบเรื่อง error 1 % ได้
2. ซีเนอร์ (`collect.py zener`), ตัวเหนี่ยวนำ (`collect.py l`), C ไม่มีขั้ว (`collect.py c`) แล้วรัน `eval_real.py`
3. C 10 µF ด้วย `autorange.py` (ต้องใช้ความถี่ต่ำ ซึ่ง `collect.py` ยังไม่รองรับ มันวัดที่ 1 kHz อย่างเดียว)
4. drift ยาว (ใช้บอร์ดตลอดเวลา จึงทำท้ายสุดหรือแยกวัน)
