# คณิตศาสตร์เบื้องหลัง DAC และ ADC (ฉบับภาษาไทย)

ไฟล์นี้อธิบายคณิตศาสตร์จริง ๆ ที่เกิดขึ้นตอน ESP32 แปลงค่าดิจิทัล → แรงดัน (DAC)
และแปลงแรงดัน → ค่าดิจิทัล (ADC) โดยอิงจากบอร์ดและโค้ดจริงในโปรเจกต์นี้
(`firmware/esp32/loopback/loopback_check/loopback_check.ino`) และข้อมูลจริงที่วัดได้
จาก Stage 2

## 1. แนวคิดพื้นฐาน: ทำไมถึงมี "ค่าดิจิทัล" กับ "แรงดันจริง" เป็นคนละเรื่องกัน

ทั้ง DAC และ ADC ทำงานกับตัวเลขจำนวนเต็ม (integer) ที่มีจำนวนบิตจำกัด ไม่ใช่แรงดันต่อเนื่อง
- **DAC (Digital-to-Analog Converter):** รับตัวเลข (เช่น 0–255) แล้วสร้างแรงดันไฟฟ้าที่
  "เทียบเคียง" กับตัวเลขนั้นออกมาที่ขา
- **ADC (Analog-to-Digital Converter):** รับแรงดันไฟฟ้าจริงที่ขา แล้วแปลงกลับเป็นตัวเลข
  (เช่น 0–4095) ที่ "เทียบเคียง" กับแรงดันนั้น

คำว่า "เทียบเคียง" สำคัญมาก — มันไม่ใช่การแปลงที่สมบูรณ์แบบ 100% เพราะความละเอียด
(resolution) ของตัวเลขมีจำกัด และวงจรจริงมี error ปนอยู่เสมอ (ตามที่เราเห็นจริงจาก
Stage 2 ไปแล้ว)

## 2. DAC: จากตัวเลข → แรงดัน

บน ESP32 ตัว DAC ที่ใช้ในโค้ด (`dacWrite(DAC_PIN, dacValue)`) เป็น **DAC 8 บิต**:

```
จำนวนระดับ (levels) = 2^8 = 256   →  ตัวเลขที่ใช้ได้: 0 ถึง 255
ช่วงแรงดันอ้างอิง (Vref)          =  0V ถึง 3.3V
```

สูตรอุดมคติ (ideal, ไม่มี error):

```
V_out = (dac_code / 255) × Vref
      = (dac_code / 255) × 3.3V
```

**ขนาด 1 stepตัวเลข (1 LSB) คิดเป็นแรงดันเท่าไหร่:**

```
1 LSB(DAC) = Vref / (2^8 - 1) = 3.3V / 255 ≈ 0.01294 V  (≈ 12.94 mV ต่อ 1 หน่วยของ dac_code)
```

หมายความว่า ถ้า `dac_code` เพิ่มขึ้นทีละ 1 แรงดันขาออก (ในอุดมคติ) จะขยับขึ้นประมาณ
12.94 mV ทุกครั้ง — นี่คือ **ความละเอียด (resolution)** ของ DAC ตัวนี้ จะให้ละเอียดกว่านี้
ไม่ได้แล้วถ้ายังใช้ DAC 8 บิตตัวเดิม

## 3. ADC: จากแรงดัน → ตัวเลข

ตัว ADC ที่ใช้ (`analogRead(ADC_PIN)`) เป็น **ADC 12 บิต**:

```
จำนวนระดับ (levels) = 2^12 = 4096   →  ตัวเลขที่ได้: 0 ถึง 4095
ช่วงแรงดันอ้างอิง (Vref)           =  0V ถึง 3.3V (โดยประมาณ ขึ้นกับการตั้งค่า attenuation)
```

สูตรอุดมคติ (แปลงกลับทาง):

```
adc_code = round( (V_in / Vref) × 4095 )
```

**ขนาด 1 LSB ของ ADC:**

```
1 LSB(ADC) = Vref / (2^12 - 1) = 3.3V / 4095 ≈ 0.000806 V  (≈ 0.806 mV ต่อ 1 หน่วยของ adc_code)
```

ADC ละเอียดกว่า DAC มาก (0.8 mV ต่อ step เทียบกับ DAC ที่ 12.9 mV ต่อ step) — นี่คือเหตุผล
ที่ ADC "เห็น" ทุกๆ step ของ DAC ได้ชัดเจน ไม่ถูกกลืนหายไปกับ noise ของ ADC เอง

## 4. ทำไม loopback สมการง่ายๆ ถึงเป็น `× 16`

เอา resolution ของ ADC หารด้วยของ DAC (โดยที่ Vref เท่ากันทั้งคู่ = 3.3V):

```
4096 / 256 = 16
```

พูดอีกแบบ: ทุกๆ 1 step ของ DAC (12.94 mV) เท่ากับ 16 steps ของ ADC (16 × 0.806 mV ≈ 12.9 mV
พอดี — ตัวเลขตรงกัน เพราะ Vref เดียวกัน) ดังนั้นในโลกอุดมคติ (DAC และ ADC สมบูรณ์แบบ,
ไม่มี error, ไม่มี offset):

```
adc_code(ideal) = dac_code × 16
```

นี่คือที่มาของบรรทัด `int expected = dacValue * 16;` ในโค้ด — มันคือสูตรอุดมคติล้วนๆ
ไม่ได้วัดจริง

## 5. ของจริงไม่ใช่อุดมคติ — นี่คือสิ่งที่วัดได้จาก Stage 2

จากข้อมูลจริงที่วัดได้ (ดู `firmware/esp32/README.md` §"Stage 2 result"), ความสัมพันธ์จริง
ไม่ใช่ `adc = 16 × dac` ตรงๆ แต่เป็นเส้นตรงที่มี **offset** กับ **gain ไม่เป๊ะ 16 พอดี**:

```
adc_code(measured) ≈ m × dac_code + b
โดยประมาณ:           m ≈ 16.0     b ≈ -231
```

และที่ปลายสุดของช่วง (dac_code ใกล้ 255) เส้นจะโค้งงอเล็กน้อย (ไม่ใช่เส้นตรงแท้ๆ ตลอดช่วง)
— แรงดันขาออกจริงของ DAC ไม่ไล่เรียบตั้งแต่ 0V ถึง 3.3V เป๊ะ มันมี **nonlinearity** และ
**offset error** ทั้งฝั่ง DAC เอง และฝั่ง ADC เอง (ปนกันจนแยกไม่ออกจากการทดสอบ loopback
แบบนี้ — รู้แค่ว่า "ผลรวมของทั้งคู่" เบี่ยงจากอุดมคติเท่าไหร่)

เหตุผลที่ทำไม `b` (offset) ถึงติดลบ (~ -231): ที่ dac_code ต่ำๆ (ใกล้ 0) วงจร DAC จริง
มักจะมี "knee" หรือช่วงที่ไม่ตอบสนองเชิงเส้นในโค้ดต่ำสุด แรงดันขาออกจริงต่ำกว่าที่คำนวณ
ไว้ตามสูตรอุดมคติ — เป็นพฤติกรรมที่รู้กันดีของ ESP32 DAC (ไม่ใช่ของเสีย)

## 6. ทำไมเรื่องนี้สำคัญกับ ML pipeline (เชื่อมกับ `calibrate.py`)

โปรเจกต์นี้ใช้ V-I signature เป็นตัวตัดสิน — ถ้าตัวเลขที่อ่านได้จาก ADC เพี้ยนไปจากแรงดัน
จริงเพราะ offset/gain error แบบนี้ รูปร่างของ signature ก็จะเพี้ยนตามไปด้วย ซึ่งจะกระทบ
ความแม่นยำของโมเดลได้โดยตรง

ทางแก้ (ตามที่ ROADMAP วางไว้ และ `firmware/esp32/README.md` เพิ่งบันทึกไว้จากผลทดสอบนี้)
คือทำ **การคาลิเบรต (calibration)** ครั้งเดียวต่อบอร์ด แล้วนำสมการย้อนกลับมาใช้:

```
จากสมการที่วัดได้:      adc_code ≈ m × dac_code + b
ย้อนกลับเป็นแรงดันจริง:  V_actual = (adc_code - b) / m × (Vref / 4095)
```

แทนที่จะเชื่อสูตรอุดมคติ `V = adc_code × Vref / 4095` เฉยๆ ซึ่งจะทำให้ค่าเพี้ยนไปตาม error
ที่เราเพิ่งวัดเจอ — นี่คือสิ่งที่ `calibrate.py` (ฝั่ง Python) หรือ firmware เอง จะต้องทำ
ก่อนที่ข้อมูล V-I จะถูกส่งต่อไปสร้าง signature

## 7. สรุปสั้น ๆ

| | DAC (สร้างแรงดัน) | ADC (อ่านแรงดัน) |
|---|---|---|
| บิต | 8 บิต (0–255) | 12 บิต (0–4095) |
| 1 step แทนแรงดัน | ≈ 12.94 mV | ≈ 0.806 mV |
| สูตรอุดมคติ | `V = code/255 × 3.3V` | `code = V/3.3V × 4095` |
| ของจริง (วัดจาก Stage 2) | มี offset + โค้งเล็กน้อยที่ปลายช่วง | รวม error ของทั้งคู่ไว้ในสมการเดียว `adc ≈ 16.0×dac - 231` |
| ทำไมสำคัญ | ต้อง "หักลบ" offset/gain error นี้ออกก่อน ไม่งั้น V-I signature จะเพี้ยน |
